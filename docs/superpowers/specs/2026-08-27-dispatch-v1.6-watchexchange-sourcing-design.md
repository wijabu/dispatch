# Dispatch v1.6 — r/WatchExchange sourcing & sales history (design)

Date: 2026-08-27
Status: approved design pending written review

## Goal

Make listing a watch on r/WatchExchange a research-assisted, low-effort flow:
Wil describes a watch loosely ("a Citizen I bought off Reddit a while back, blue
dial, radio-controlled"), and Dispatch + Claude turn that into a ready-to-post
`[WTS]` in Wil's own house format — without building each listing from scratch.
Two supporting outcomes: (1) learn Wil's actual posting patterns from his full
WatchExchange history so the generated posts read like his, and (2) capture his
past and future watch sales as tracked Dispatch records (date, price, watch,
post link).

This does NOT build the automated web posting flow — that stays backlogged (see
Not in scope). Wil shoots photos, uploads to imgur, and posts himself, the same
copy/paste floor OfferUp and Facebook already have.

## The organizing principle: script vs. AI

The work splits cleanly, and the split is the architecture:

- **The template is a pure script** — turning known watch attributes into a
  `[WTS]` post + details comment is deterministic string assembly. It is the
  existing `reddit-watchexchange` publisher (a pure, unit-tested function),
  extended to Wil's format. No AI, no tokens, versioned.
- **The research is AI (Claude, interactive, per watch)** — fuzzy-matching a
  vague description to a specific past post, and extracting specs from
  free-text Reddit threads or web spec sheets, is judgment over unstructured
  text. No reliable free "watch specs by reference" API exists to script
  against, so this half is genuinely AI. It is one-time per watch and cheap.

This honors the cost rule: script the deterministic part, use AI only where a
script cannot do the job.

## Scope decisions (from brainstorming, all user-approved)

1. **Fuzzy NL sourcing.** Wil describes a watch loosely; Claude searches his
   history to identify the specific post (a *buy* → his comment history; the
   description is the query), or falls back to the web.
2. **Output lives in Dispatch as a tracked item**, reusing the item + listings
   + publisher architecture (and the v1.5 sold fan-out), not a standalone draft.
3. **Wil's house format**, learned from his real posts: title-only post (title +
   one or more images, no body); full detail in his own **first comment** with
   an **external imgur album link**. Title pattern from his samples:
   `[WTS] Brand - Model - Variant/Dial - Kit status`
   (e.g. `[WTS] Oris - Big Crown Pointer Date - Oxblood - Full Kit`).
4. **Sales history is tracked as items**, the same model that records every
   other sale — no separate store.
5. **Confirm before fill.** Claude presents researched specs for Wil to
   confirm/correct before anything is written; never fabricates a spec (a value
   not found is left blank / "not measured", never invented).

## Two phases

### Phase 0 — learn the corpus (once)

Pull *every* `[WTS]` Wil has posted to r/WatchExchange plus his first comments,
and his relevant buy-side comments, then:

- **Extract his posting profile:** title convention, comment structure, spec
  ordering and labels, standard lines (shipped CONUS, timestamp, imgur album),
  tone, photo conventions. This profile becomes the concrete template spec the
  publisher implements — the script reproduces *Wil's* format, not a generic one.
- **Seed sales history:** each past `[WTS]` becomes a Dispatch item (status
  `sold` where confirmed, else `archived`) plus a `reddit-watchexchange`
  listing row whose `url` is the post link, `listedPrice` = asking price,
  `listedAt` = post date, `soldAt`/`soldPrice` where known. Created through the
  **existing item-creation path** (the same `createItem`/listings writes the app
  already uses), as a one-time seed during Phase 0 — no new bulk-import UI or
  feature (YAGNI).

Phase 0 is the discovery that defines the template, so it precedes the template
code. Its output is reviewed with Wil before it drives anything.

### Phase 1 — per watch (repeatable)

1. Wil gives a loose description + his asking price + condition (+ "bought on
   Reddit ~when", if so).
2. Claude sources specs: his Reddit history for the original thread, else web
   spec sheets.
3. Claude shows the researched specs; **Wil confirms or corrects**.
4. On approval, the watch item's attributes are filled in Dispatch.
5. The `reddit-watchexchange` publisher (the script) generates the title-only
   post + the details comment in Wil's format.
6. Wil shoots photos, uploads to imgur, pastes the album link, and posts. The
   imgur album and the current-dated timestamp photo stay manual.

## Data model

Reuses the existing schema; two small additions.

- **Items track the sale** exactly as today: `status=sold`, `soldPrice`,
  `soldAt`, `soldChannel`, plus a `listings` row (`publisher`, `url`,
  `listedPrice`, `status`, `listedAt`). A watch = an item; its specs live in the
  free-form `attributes` JSON.
- **Add channels to the `SOLD_CHANNELS` enum:** today `offerup | facebook |
  craigslist | other`; add `reddit-watchexchange` and `watchuseek` so the sold
  channel is first-class (additive migration, matching v1.5's pattern). Listing
  `publisher` is already free text, so the ledger side needs no change.
- **Add watch attribute suggestions** to `src/config/categories.ts` `watches`
  (today: Brand, Model, Reference, Movement, Diameter, Box/Papers, Accessories,
  Year). Add the fields Wil named and WatchExchange norms use: **Crystal, Case
  Material, Strap/Bracelet, Lug Width, Water Resistance, Dial, Features**. These
  are suggestion chips on the item form — free-form, nothing required.

## The template (publisher enrichment)

Extend `src/publishers/reddit-watchexchange.ts` to emit Wil's two-part format.
The format is built now from the two sample posts + WatchExchange norms, and
refined if/when the Phase 0 corpus is available — the template code is not gated
on Phase 0 (that only tunes spec ordering/labels/wording).

- **Post block:** the title only (the `[WTS] Brand - Model - Variant - Kit`
  pattern), no body — Wil attaches the image(s).
- **Comment block:** the full details for Wil to paste as his first comment —
  spec list in his ordering, condition, price ("shipped CONUS"), and a labeled
  placeholder line for the **imgur album link** and the timestamp reference.

The publisher stays a pure function of `(item, photos)` returning
`{ title, body, warnings }`, where `title` is the post and `body` is the
comment block. Deterministic and unit-tested against fixtures.

## Research playbook (the AI half)

Not code — a documented workflow Claude follows:

- **Query:** Wil's loose description. **Match:** his Reddit history (buys in his
  comment history; sells in his submissions) or web spec sheets.
- **Confirm-before-fill:** present a spec table; Wil corrects; only then write.
- **No fabrication:** unknown specs left blank; unknown sold prices recorded as
  "not measured", never estimated (public posts give watch + link + asking +
  post date reliably; negotiated sold price is usually private).

## Access constraint (important)

Reddit blocks automated reads from this environment on every path tried:
sandbox browser + WebFetch are policy-blocked for `reddit.com`; unauthenticated
`curl` to the public JSON API returns HTTP 403 (Reddit anti-bot). The only route
that defeats the 403 is a **real logged-in browser via Claude in Chrome**, which
requires the Chrome extension connected to Wil's account (currently shows 0
connected browsers). Fallbacks if the extension is impractical: Reddit's own
account data export, or Wil pasting his post/comment list. Phase 0 is gated on
one of these; the design and template code are not.

## Error handling / honesty

- Missing specs degrade gracefully — the publisher already skips empty fields.
- Unknown sold price → not recorded as a number; the item keeps asking price and
  a null `soldPrice`.
- A watch that can't be matched in Reddit history falls back to web specs, and
  if neither resolves, Claude says so rather than guessing.

## Testing

- **Publisher (script):** unit tests over fixtures — a full-kit watch yields the
  right title-only post + a details comment with specs/condition/price and the
  imgur placeholder; a sparse watch omits empty fields; title matches the
  `[WTS] Brand - Model - Variant - Kit` pattern.
- **Enum + attributes:** additive migration applies cleanly; new suggestion
  chips render on the watch item form.
- **Phase 0 / research:** manual + AI, reviewed with Wil (no unit tests — it
  reads live external data).

## Explicitly not in scope

- **Automated web posting to Reddit** — remains backlogged (Firefox staged
  handoff); this feature stops at generating copy/paste content.
- **imgur upload and the timestamp photo** — manual (Wil shoots/uploads anyway).
- **Reddit account seasoning / karma** — Wil's existing account handles this.
- **A dedicated structured watch-spec schema** — attributes stay free-form JSON
  per Dispatch's existing design (YAGNI for personal use).
